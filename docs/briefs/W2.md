# W2 brief: the one logged channel (MCP tool server)

Clean Sheet watches a solo founder's AI worker agents. W1 built the Keeper engine in `src/keeper/` (read `result.md` from W1 if present, and `src/keeper/engine.js`). Your job: the channel every QwenWork worker agent goes through. Context: `docs/battleplan.html` sections 05 and 08.

## Hard rules

- Plain JavaScript ES modules, Node 24, **no npm dependencies, no installs, no network**. Tests use `node:test`. Add scripts to the existing `package.json`; keep `npm test` passing, including W1's tests.
- Do not change the engine's decisions. If you must change `src/keeper/`, keep `node scripts/score.js` at its current score or better, and list every change in `result.md`.
- **Never write to `fixtures/`.** At startup copy the overlaid data (`fixtures/starter-kit/data` + `fixtures/extra/data`) into `runtime/workspace/` and act on that copy. `runtime/` is git-ignored (add it to `.gitignore`).
- Do not run git. Do not commit.

## Build

1. **MCP server**, hand-written JSON-RPC 2.0, in `src/mcp/`:
   - Methods: `initialize`, `notifications/initialized`, `ping`, `tools/list`, `tools/call`. Return MCP-shaped results (`content: [{type:"text", text}]`, plus `isError` when blocked).
   - Transports: **stdio** (`node src/mcp/stdio.js`) and **HTTP** (`node src/mcp/http.js`, default port 8787): Streamable HTTP style `POST /mcp` returning JSON, and a legacy SSE pair (`GET /sse` + `POST /messages?sessionId=`). QwenWork accepts stdio or SSE/HTTP; see `C:\Users\Woo\.qwenwork\skills\qwenwork-guidance\guide-mcp.md` (read only) for the config shapes it expects.
   - Tools: `start_task(agent, instruction, scope?)`, `end_task(task_id)`, `list_files(folder)`, `read_file(path)`, `send_email(to, subject, body, attachments?)`, `quote_price`, `accept_terms`, `pay_supplier`, `order_from_supplier`, `upload_to_external_tool`, `delete_file`. Clear descriptions and JSON schemas so an LLM agent uses them right. Calls without an open task get a default task per agent.
   - Every call goes through the engine. **ALLOW**: run it on `runtime/workspace` (emails are written to `runtime/outbox/<id>.json`, uploads to `runtime/uploads/`, deletes really delete from the workspace copy, R17 notifications go to the outbox). **HOLD**: add to the approval queue and tell the agent "Held for the owner's approval: <reason>". **BLOCK**: tell the agent "Blocked by the Keeper: <owner_message>". Blocked or held reads return no file content.
2. **Event stream and audit log**: append every contract event to `runtime/events.jsonl` and every decision to the hash-chained log (W1's `log.js`).
3. **Console API** on the same HTTP server: `GET /api/events` (SSE live stream, replays history first), `GET /api/queue`, `POST /api/queue/:id/release`, `POST /api/queue/:id/reject` (release runs the held action and emits `owner.decision` + `action.executed`), `GET /api/scorecard` (runs the scenario suite and the normal set and returns totals), `GET /api/log/verify`, `GET /api/briefing?date=`. CORS open for GET and POST.
4. **Rogue runner**: `node scripts/rogue.js [--http http://localhost:8787]` drives S1 to S7 from `tests/harness.json` **through the MCP protocol** (spawn the stdio server, or call the HTTP one), interleaved with normal actions. Print the kit-style score at the end; it must match `scripts/score.js`.
5. **Briefing**: `src/briefing.js` turns one day of the log into (a) a 60-second script, 140 to 160 words, plain words for a non-technical owner, in the kit's owner-message style: what was blocked, what waits in the queue and the money at stake, what an agent read that it did not need, and "nothing was sent" where true; and (b) JSON counts. Template-based, no LLM. `node scripts/briefing.js` prints it for the latest day.
6. **Replay**: `node scripts/replay.js runtime/events.jsonl --speed 4` re-emits a saved run onto `/api/events`, for the demo backup.
7. **Gate test**: `scripts/mcp-hello.js`, a tiny standalone stdio MCP server with one tool `keeper_ping` that returns "Clean Sheet MCP reached at <time>". For a first live test in QwenWork.
8. **Docs**: `docs/connect-qwenwork.md`: exact steps and config JSON to add `mcp-hello`, then the stdio server, then the HTTP/SSE server, as custom connectors in QwenWork desktop, using absolute Windows paths for this repo. Mention that cloud scheduled tasks will need the HTTP server hosted at a public URL.

## Tests

Handshake + `tools/list` + one ALLOW, one HOLD and one BLOCK over stdio (spawned process) and over HTTP; queue release; log verify after a full rogue run; briefing word count 140 to 160 and it mentions the S5 reads.

## When done

Write `result.md`: `npm test` summary, rogue runner output, the briefing text it produced, files made, judgement calls, known gaps. Under 120 lines.
